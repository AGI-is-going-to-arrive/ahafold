同一张网页，三种工作

初学时，HTML、CSS 和 JavaScript 很容易被当成三门可以互相替换的“做网页语言”。更清楚的记法是：它们叠在同一页上，各管一件不同的事。

先把三个术语分开

HTML provides the page structure：它标出标题、段落、按钮这些部件，告诉浏览器“这一页里有什么、它们是什么”。

CSS 决定颜色、间距和版式：部件已经在，它负责这些部件看起来怎样、彼此隔多远、怎样排。

JavaScript adds optional behavior when the reader interacts with the page：读者点击、输入或做其他操作时，页面可以多做一件事；不操作，原有内容通常仍能阅读。

HTML 搭结构，CSS 管外观，JavaScript 只在互动时加上可选行为。三者不是三个版本的同一件事。

用同一张告示对照

下面这张图书馆告示始终是同一页内容。切换选项时，变的不是题目，而是这一页上哪一种工作被点亮。

同一张告示，三种工作

标题今日告示

段落图书馆周六闭馆。

按钮查看开放时间

读者点过按钮后：周日 9:00–17:00 开放。

HTML · 结构标题、段落、按钮都已标出。没有颜色和间距安排时，内容仍在，只是看起来像未排版的草稿。

CSS · 外观同一组部件被加上颜色、间距和版式。告示更好读，但按钮此时还不会变出新句子。

JavaScript · 可选行为读者互动之后，才多出“周日开放时间”。这行不是结构本身，也不是颜色或留白。

示意里的按钮不能真的点按；第三项用已经出现的那行字，代表“互动之后才加上的行为”。三种说明始终都在，不依赖颜色来区分。

术语对照

把三个英文术语放回同一张表里。中间一列是这份材料给出的职责；右侧是入门时可用的记法，不是完整技术定义。

术语 这份材料里它做什么 可以这样记
HTML provides the page structure（提供页面结构） 这一页有哪些部件，每个部件是什么。
CSS 决定颜色、间距和版式 这些部件看起来怎样、隔多远、如何排列。
JavaScript adds optional behavior when the reader interacts with the page（读者互动时加上可选行为） 有人操作后，页面可以多做什么；不操作，原页仍在。

写在代码里，会看到什么

结构常常先写成标记。下面只有 HTML，还没有写出颜色，也没有写出点击后要发生的事：

<h1>今日告示</h1>
<p>图书馆周六闭馆。</p>
<button type="button">查看开放时间</button>
HTML
给出 h1、p、button 这三个部件。
CSS
另写规则，指定字号、留白、颜色和按钮形状。不改上面这三个部件“是什么”。
JavaScript
另写脚本，在按钮被使用后插入开放时间。没有这段脚本，告示仍可阅读。

这张对照停在哪里

这是按所给材料做的入门分工，方便把三个词先分开。它不是互斥的能力清单，也不表示某一项“只能”或“永远不能”做另一项的事。

例如：CSS 也能在指针悬停时改变颜色，不必写 JavaScript；JavaScript 也能在无人点击时运行，例如计时更新。HTML 里偶尔也能写到外观相关的属性，但入门时仍应把它记成结构。

房子骨架 / 粉刷 / 门铃这样的比喻只用来记住分工。真实网页里三种技术经常写在一起，并且还可以配合图片、无障碍属性、服务器逻辑等这里没有展开的部分。

少了其中一项，初学者会看到什么？

按这份材料的模型：没有 HTML，就没有这些被标出来的标题、段落和按钮。没有 CSS，内容通常还在，只是颜色、间距和版式未经指定，浏览器会用默认样子显示。没有 JavaScript，页面仍可阅读，只是读者互动后不会出现那件可选的额外行为。

实际项目里，缺哪一层、缺到什么程度，取决于作者怎么写，不能从这一页推出所有网站的必然结果。
