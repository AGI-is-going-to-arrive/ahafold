HTML、CSS 与 JavaScript
不是同一件事

做网页常会同时听到三个英文术语：HTML、CSS、JavaScript。初学者容易把它们当成「写网页的同一种语言」。它们可以出现在同一页里，但各管一件不同的事。

先记住这一句分工

HTML 提供页面结构：哪些是标题、哪些是段落、内容按什么顺序出现。CSS 决定颜色、间距和版式，也就是看起来怎样。JavaScript 不负责把内容「写出来」，它只在读者与页面互动时，加上可选的行为。

同一页里：HTML 管结构，CSS 管样子，JavaScript 管可选的互动。

三者叠在同一页上

可以想成三层：最底下是能读的骨架，中间是外观，最上面才是互动。没有上一层，下一层往往仍能单独成立。

并排对照，避免混用

判断自己有没有把术语用混，可以问：这句话说的是「里面有什么、按什么顺序」，还是「看起来怎样」，还是「点了以后会怎样」。

术语 它管什么 没有它会怎样
HTML 页面结构：标题、段落、列表、谁先谁后 没有可阅读的内容骨架，页面无从谈起
CSS 颜色、间距、版式 内容往往仍可读，但几乎是浏览器默认的样子
JavaScript 读者互动时的可选行为 页面仍可阅读、仍可有样式，只是少了点击或输入后的变化
HTML

提供页面结构。它回答的是：这一页有哪些部分，它们怎样排列成一份可读的内容。

英文术语保持为 HTML。教学上可把它想成「骨架」，但骨架只是比喻，不是技术文件名。

CSS

决定颜色、间距和版式。结构已经在 HTML 里，CSS 改的是观感：字大不大、块与块隔多远、文字如何排布。

没有 CSS，HTML 结构通常还在。有 CSS，也不等于页面会自己响应点击。

JavaScript

在读者与页面互动时，加上可选行为。例如按下按钮后出现一段说明，或输入后检查是否填完。

资料里的关键词是「可选」：一页可以只有 HTML，或只有 HTML 加 CSS，仍然是网页。

这个对照停在哪里

「三层叠在一起」只用来分清职责。真实项目里，这三者可以分开放在不同文件，也可以写在同一份文件里；HTML 里偶尔也会出现影响外观的属性。那是后一步的细节，不推翻「结构 / 样子 / 可选行为」这条入门界线。

本页也不声称：学网页必须按这个顺序写代码，或 JavaScript 比另外两者更高级。它只说明三个英文术语各自在说什么。

如果一页只有 HTML，还算网页吗？

算。只有 HTML 时，读者仍然能看到标题、段落等结构，只是颜色、间距和版式多半是浏览器默认值，并且缺少点击后的额外变化。

加上 CSS，改变的是看起来怎样。再加上 JavaScript，才是在互动发生时添加行为。这三步不是「三种网页」，而是同一页上可以叠加的职责。

来源与说明

正文依据用户提供的三句材料改写，供初学者对照术语，未另查 HTML、CSS 或 JavaScript 规范：

  • HTML provides the page structure.
  • CSS 决定颜色、间距和版式。
  • JavaScript adds optional behavior when the reader interacts with the page.

「骨架 / 外观 / 互动」是教学比喻，不是规范用语。分层图表示职责关系，不表示浏览器内部如何实现，也不表示必须分成三个文件。
