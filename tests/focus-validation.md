# Codex / Grok：多语言、多场景验收

日期：2026-09-05。Antigravity CLI 按用户要求暂缓，本轮没有调用它。

**结论：真实安装、真实调用和多维评估均已进行，但不能宣布所有场景全面通过。**
Codex 本批覆盖的主要结果较好；Grok 有事实矛盾、图文不符、细小计算误差、手机阅读问题及未完整结束的任务。这里不把运行成功、漂亮图片、静态检查或 CI 通过等同于内容正确。

## 方法与证据边界

- 在新的隔离项目中，通过固定版本 `skills@1.5.23` 从私有远端安装 Codex/Grok 各自的技能；核对9个包内文件哈希及无符号链接。R1 在新目录从修改后的本地技能安装，指纹另存。
- 本轮24次真实宿主会话：18次零图边界／技术测试，Grok 英文新作与两种语言修订3次，Grok 复利原作与0%修订2次，Codex 仅图片编辑1次。4次因超时或回合上限未正常完成，单独记录。
- 新增3次图片调用：Grok 英文新图、Grok 使用包内母版生成复利场景、Codex 双输入参考编辑。与前轮合计 **9/15**；本轮无自动重发、无其他宿主 fallback、无 Antigravity 调用。
- Codex CLI0.153.4、Grok Build1.0.13，macOS26.6.2。使用现有 OAuth；不提取凭据、不更改全局权限／模型配置。图片费用未知；Grok 的文字调用成本字段是宿主估算，不是账单。
- 新 Grok E02/E03 使用简短用户请求、公开资料与预算，未提供角色画法、完整构图、HTML布局、测试答案或控件ID。由宿主发现并读取安装的技能和当前宿主参考。仍不是无资料或真人首次上手实验。
- 保留首轮与R1原始产物。审阅和浏览器检查不改原文件；不会把后续修正算成首轮通过。完整文件与脱敏记录见 [focus/](focus/README.md)。
- Codex JSON事件不包含完整原生图片轨迹，调用次数结合新文件、工具结果和会话陈述判断。Grok读取HTML可能自动附带图片，不能仅凭ACP文本日志断言“模型没有看到图”；相关水印观察疑点已撤回为未确认。

## 需要保留的失败

1. **Grok术语页：事实正确性失败，R1后仍未解决。** 首轮写“JavaScript不负责把内容写出来”“只在读者互动时执行”；R1在主结论保留“只在互动时”，后文又承认定时器无需点击。真实离线反例证明：脚本可在页面加载时创建正文，原生details无需JavaScript即可交互。[首轮](focus/artifacts/grok-terms-initial/index.html)、[R1](focus/artifacts/grok-terms-r1/index.html)。额外控件只是信息效率评审意见；原请求并未明确禁止所有交互。
2. **Grok英文辨析：图文对应失败。** 图片里茶杯在最左卡片，小折左臂靠近钥匙卡；右侧没有明确绘画动作。alt却称指向茶杯并产生茶杯。标签与身份正确，不足以通过核心机制验收。[原图／三版页面](focus/README.md)。
3. **Grok技术页：未完成且存在编译期／运行时矛盾。** 将擦除的`as User`画为第四执行步骤，并使用“断言通过”“保证四步走完”等字样，与自己的失败分支说明冲突。600秒时仍未正常结束，手机还溢出37px。[页面](focus/artifacts/grok-technical/index.html)。
4. **Grok复利：差额有1分舍入误差。** 使用已经取两位的265.33和188.56相减得到76.77；保留计算精度后结果是76.76。所有21个状态已在浏览器实际采样，原始文件未修补。[数值记录](focus/browser-results.json)。
5. **四次流程未完成。** 原始混合技术任务两宿主都触及300秒；改用物理规范路径并放宽到600秒后，Codex在475.6秒完成，Grok仍超时；另一个Grok0%英文任务退出1、触及18轮上限。这些环境／资源条件与原始记录均保留，不伪装成产品功能通过。

对提供的TypeScript函数还运行了7个离线受控反例：404不解析JSON，HTML或204空body解析失败，错误字段类型和null仍可返回，网络错误在Response前拒绝。没有真实API请求。[记录](focus/technical-counterexamples.json)。

## 修改与发布判断

R1只增强3处薄指令：不把角色分工写成排他能力；未能看图时HTML与交付状态都保留待核验；语言修订保留不确定性与代码标识。它没有增加数据库、服务、统一SDK或跨宿主fallback。**R1的Grok复测仍失败，因此不能宣称这些提醒已解决生成可靠性。**

另新增维护者真实安装器生命周期测试；安装单元仍只有9个技能资源。原始失败产物在测试目录明确标注，不替换主README中的已审核示例。此前基线的PASS只代表当时的受限安装到产物链路；Grok当前应按部分通过并要求内容与图像复核理解。

本轮足以给出有证据的多维评估，**不足以宣布“全场景全面通过”或无人工复核可正式发布**。仓库始终私有，Antigravity暂缓，其他平台的原生宿主测试仍是未测。
